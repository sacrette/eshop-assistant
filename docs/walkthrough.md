# 本地演示流程

按这个顺序走，三分钟内能看到四个角色页面的主要能力。全程用本地种子数据，不需要外网。

## 准备

```powershell
uv run python -m scripts.dev
```

打开 http://127.0.0.1:8010 ，登录页点演示身份会自动填入邮箱与密码。

| 角色 | 账号 | 数据 |
| --- | --- | --- |
| 用户 林悦 | `lin@eshop.demo` | 4 笔订单，含已签收、已发货、待付款 |
| 用户 周然 | `zhou@eshop.demo` | 用于验证看不到林悦的数据 |
| 客服 陈曦 | `agent@eshop.demo` | 售后审核与知识运营 |

## 用户侧

1. 用林悦登录，进入「智能客服」，输入「订单 ES20261018001 的猫砂盆能退吗」。
2. 预期：回答带 `[1]` 角标，右侧「处理过程」显示本轮意图、证据置信度与候选知识。
3. 选择订单、填「七天无理由」提交，弹出确认框；取消后不写业务记录。
4. 「我的售后」里出现状态为「待审核」的申请。

## 客服侧

1. 换陈曦登录，进入「售后工作台」，在队列中找到刚才那张申请。
2. 核对订单号、原因与提交时间，填写审核意见后批准；时间线新增一条事件。
3. 点「记录处理完成」，状态变为已处理（仅表示本地处理结束，不代表打款）。
4. 越权检查：用周然登录访问林悦的售后单，接口返回 404。

## 知识运营

1. 回到陈曦，进入「知识运营」，问题池里应有一条来源为「检索证据不足」的问题。
2. 点「整理新问题」，问题被标准化并归到「待审核」，右侧显示来源会话与出现次数。
3. 编辑答案后点「审核并发布」；索引失败时状态留在待审，可重试。

## 知识库

1. 进入「知识库」，顶部四个数字：知识块数、待向量化、Milvus 条数、双写一致性。
2. 「录入与预览」选择 `returns-policy.md`，查看切块数、表格块、关键条款与重复标记。
3. 「检索自测」输入「退货运费谁出」，切换纯向量 / BM25 / 混合 / 混合+重排，对比第一条证据是否一致。

## 异常路径

- 未配置聊天模型时，`/api/chat` 返回 503，页面显示真实不可用状态。
- 未启动 Milvus 时，知识库页的 Milvus 显示离线、双写一致性为「—」，检索自测返回 502。
- 容器未启动时先执行 `docker compose up -d`，`scripts/dev.py` 会等待健康检查。
