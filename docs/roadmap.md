# 范围与里程碑

面向电商咨询与售后的客服工作台：用户咨询商品政策、查看自己的订单并确认售后申请；客服核对申请并记录处理结果；运营审核知识缺口，发布经过索引的答案。

## 范围

- 用户端：流式会话、证据引用、订单选择、工单确认与取消、售后申请、未解决反馈。
- 客服端：售后申请队列、订单详情、审核意见、状态时间线、人工待办与相关对话。
- 知识运营：三类缺口来源、问题归并、答案审核、索引失败重试、发布状态。
- 知识库：材料切块预览与查重、入库、补齐向量、四策略检索自测、挖掘结果人工采纳。
- 服务端：会话认证、CSRF 校验、订单与会话归属校验、幂等提交、售后状态版本控制、工具审计。
- AI 核心：LangGraph 编排、interrupt/resume、混合检索与重排、证据置信度、异步滚动摘要。
- 观测：LangSmith 回调、`thread_id` 关联、按意图聚合根调用 token 用量。

## 技术决策

| 方面 | 选择 | 理由 |
| --- | --- | --- |
| 前端 | React 19 + TypeScript + Vite + Radix Dialog + Lucide | 三个角色任务各自成页，确认类弹窗需要焦点管理 |
| 后端 | FastAPI（业务与 SSE） | 与前端同仓，构建产物由 FastAPI 直接托管 |
| 存储 | MySQL 为业务库；SQLite 用于隔离测试与 LangGraph checkpoint | 测试不依赖容器，checkpoint 单独落文件 |
| 检索 | Milvus + BM25 + 重排，四策略可切换 | 便于用同一评估集对比策略 |
| 观测 | LangSmith，默认关闭 | 缺少密钥时不影响业务 |

## 里程碑

| 阶段 | 内容 | 状态 |
| --- | --- | --- |
| M1 | 固定订单、售后单、事件记录与认证会话；身份隔离、状态转移、幂等提交 | 已完成 |

## 暂缓与不做

| 项 | 原因 |
| --- | --- |
| 真实物流与支付对接 | 没有可用沙箱；用本地快照适配器替代，接口形状保持不变 |
| 多租户 | 当前是单店铺演示，隔离只做到用户级（看不到别人的订单与会话） |
| 跨进程并发恢复 | 按单 API worker 部署；需要共享会话锁与分布式 checkpoint 才有意义 |
| MySQL 端到端验证 | 业务验证走 SQLite 隔离库；MySQL 只保证容器、建库与迁移脚本可用 |
| LangSmith 云端 trace | 需要账号密钥与真实调用，本地测试无法替代 |

## 验收场景

1. 用户甲看不到用户乙的订单、会话、待确认操作和售后单。
2. 同一幂等键重试返回原售后单；更换内容但复用键返回冲突；同一订单已有进行中申请时不重复建单。
3. 客服可审核与驳回，只有已批准的申请可以完成；完成表示本地售后处理结束，不宣称真实打款。
4. 聊天中断可读取并恢复，确认前展示当前操作，取消不写业务记录。
5. 无模型、Milvus 或 LangSmith 凭据时页面显示真实不可用状态，不生成伪造的回答或指标。
